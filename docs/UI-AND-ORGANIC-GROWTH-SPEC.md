# 观己 · UI设计与自然传播机制说明

状态：面向开发团队的产品规格，未实现  
产品基线：免费大五 / ¥9.9完整四维 / ¥99＋人工1对1沟通  
相关文档：[`LANDING-PAGE-COPY-V1.md`](./LANDING-PAGE-COPY-V1.md)

## 0. 目标与边界

本文档细化两类能力：

1. 视觉与交互设计方向。
2. 与产品方法论直接相连的自然传播机制。

传播功能不使用“邀请多人解锁”等外挂式裂变机制。所有传播行为必须是用户主动选择的产品功能，不得默认公开或隐式暴露测评数据。

# 一、UI设计

## 1. 视觉调性基础

产品文案的核心风格是精确、克制、不过度承诺。视觉设计需要延续同一语气。

### 设计要求

- 白、浅灰、深灰等中性色作为基础色。
- 强调色控制在1–2个之内，用于 CTA、当前进度和关键结果。
- 优先通过留白、排版、字重和分隔建立层级。
- 不使用鲜艳多彩的糖果色、宝石人格测试式配色、装饰性徽章、发光效果或大面积渐变。
- 不用多层阴影堆叠浮动感。如需表达层级，优先使用边框、底色和间距。
- 任何状态不得只依赖颜色区分。

### 验收条件

- 主色、强调色和状态色有统一设计变量。
- 正文、辅助文字、按钮和图表标注符合 WCAG AA 对比度要求。
- 关闭颜色后，仍能通过文字、图标或形状识别关键状态。

## 2. 模块进度组件

价值观、兴趣、大五、潜力证据与成长条件、九型使用同一套进度组件。四维为核心模块，九型为可选动机补充。

### 状态

| 状态 | 文字 | 非颜色标识 | 可用动作 |
| --- | --- | --- | --- |
| 待解锁 | 待解锁 | 锁图标 | 查看权益说明 |
| 未开始 | 未开始 | 空心圆或短横线 | 开始 |
| 进行中 | 进行中 | 进度图标＋题数 | 继续 |
| 已完成 | 已完成 | 对勾 | 查看结果或修改 |
| 可选跳过 | 可选 · 已跳过 | 跳过图标 | 重新开始 |

### 数据来源

- 状态必须绑定用户的实际模块级答题进度，不使用静态占位数据。
- 进行中状态至少包含 `answeredCount`、`requiredCount`、`lastSavedAt` 和 `moduleId`。
- 本机测评从本地记录读取；已登录付费用户从云端记录读取。
- 状态冲突时，不静默覆盖；需要按产品设计处理时间更新或显示恢复选项。

### 权益呈现

- 免费用户：大五显示实际状态；价值观、兴趣、潜力证据和九型显示“待解锁”，不显示“未完成”。
- ¥9.9用户：大五50题、价值观、兴趣、潜力证据可用；九型显示为可选。
- ¥99用户：包含¥9.9权益、大五120题、PDF和人工沟通；九型显示为可选。

### 验收条件

- 刷新页面后，模块状态与已保存记录一致。
- 免费用户不会被暗示“遗漏完成”未购买模块。
- 光标、键盘焦点和屏幕阅读器都能识别模块状态和可用动作。

## 3. 结果可视化图表

### 霍兰德兴趣

- 使用 RIASEC 六维雷达图。
- 固定维度顺序：R、I、A、S、E、C。
- 每维输入0–100分。
- 同时提供文字分数表，不让雷达图成为唯一信息载体。

### 大五人格

- 移动端优先使用横向条形图，便于阅读维度名和分数。
- 五个维度：开放性、尽责性、外向性、宜人性、情绪稳定性。
- 每维输入0–100分。
- 不将分数表述为人群百分位、能力或成功率。

### 技术要求

- 可使用 Chart.js 的 radar/bar 类型或等价的轻量图表方案，不自研图表引擎。
- 图表必须能稳定导出为静态图片，供 PDF 和分享卡片复用。
- 实现前确认导出链路：直接 canvas 导出，或 SVG 转 PNG。
- 导出图片需要嵌入或使用可预测的中文字体，避免服务端缺字或替换字体。
- 图表需要提供可访问的文字摘要。

### 验收条件

- 320px宽屏幕不溢出、不遮挡标签。
- 图表、文字分数和报告数据一致。
- PNG/PDF 导出后字体、颜色和标签完整。

## 4. 移动端优先

主要获客渠道为小红书等移动端场景，移动端是首要验收环境，不是桌面版的事后缩放。

### 设计要求

- 长段落在小屏上检查自然换行。单个默认可见段落建议不超过3–4行，超出时使用“展开”。
- 按钮、模块项、CTA、折叠控件和图标按钮至少提供44×44px触控热区。
- 首屏优先展示核心承诺和免费 CTA；详细模块说明放在首屏之后或默认收起。
- 不使用只有 hover 才能了解的交互。
- 底部固定 CTA 不得遮挡题目、选项、键盘或系统安全区。

### 验收视口

- 320×568。
- 375×812。
- 390×844。
- 430×932。
- 一个常用桌面视口作为补充验收。

## 5. PDF导出样式

当前依赖浏览器打印生成 PDF。必须维护独立打印样式，不直接将屏幕布局当作最终 PDF。

### 实现要求

- 使用 `@media print` 定义打印布局、字号、页边距、显示和隐藏规则。
- 对需要保留颜色的图表、状态和色块使用 `print-color-adjust: exact` 与 `-webkit-print-color-adjust: exact`。
- 图表、表格、结果卡和标题与正文组使用 `break-inside: avoid` 或等价分页规则。
- 交互控件、导航、底部 CTA 和不需要进入报告的说明在打印时隐藏。
- 页眉、页脚、报告版本和生成日期使用稳定格式。

### 验收条件

- 逐页检查 PDF，不只验证“能下载”。
- 图表、表格和文字不从中间被截断。
- 彩色和黑白打印均能识别关键结果。
- 中文字体不丢失，长文本不溢出页边界。

# 二、自然传播机制

## 6. 结果分享卡片

### 功能

- 免费大五完成后，默认展示“生成分享卡片”入口。
- 只有用户主动点击后才生成图片；不默认生成，不自动下载，不自动分享。
- 用户可以预览、保存图片或调用系统分享能力。

### 卡片内容

- 测评名称。
- 大五五维简要图表或数值。
- 一句与结果一致、不过度推断的总结。
- 指向网站的二维码或短链。
- 不默认包含姓名、用户名、手机号、邮箱、学校或其他可识别信息。

### 技术实现

- 优先使用服务端图片渲染：无头浏览器截图固定模板，或专用图片生成方案。
- 不依赖用户设备的页面截图作为唯一方案，避免字体、屏幕比例和浏览器差异。
- 生成请求只传入卡片所需的结果字段，不传输完整答题记录或账号信息。
- 短链和二维码不包含可猜测的用户ID或测评ID。

### 验收条件

- 未点击“生成”前，服务端不产生分享图片或公开链接。
- 同一结果在常用移动设备上生成的字体、尺寸和排版一致。
- 分享卡片不泄露不必要的个人数据。

## 7. 对比机制（邀请对比）

### 用户流程

1. 发起人完成至少免费大五。
2. 发起人主动选择“邀请朋友对比”并生成有期限的邀请链接。
3. 被邀请人打开链接，完成至少免费大五。
4. 系统明确询问被邀请人是否同意查看对方结果并向对方展示自己的结果。
5. 发起人和被邀请人均完成确认后，对比视图才可用。
6. 任一方拒绝、撤回同意或邀请过期时，对比不可见。

### 状态

- `pending_assessment`：被邀请人尚未完成测评。
- `pending_invitee_consent`：被邀请人尚未确认可见。
- `pending_initiator_consent`：发起人尚未完成最终确认。
- `active`：双方同意，可查看对比。
- `declined`：任一方拒绝。
- `revoked`：任一方撤回同意。
- `expired`：链接超过有效期。

### 数据模型要求

对比邀请至少记录：

- 发起人ID或结果引用。
- 被邀请人ID；未登录时使用不可猜测的匿名结果 token。
- 邀请 token 的安全哈希，不在数据库中保存可直接使用的明文 token。
- 邀请状态。
- 双方同意时间与撤回时间。
- `expiresAt`，建议有效期7–14天。
- 创建、更新和最后访问时间。

### 隐私要求

- 双方同意前，任一方都不得查看另一方的分数、图表或文字结果。
- 邀请链接本身不展示发起人的完整结果。
- 撤回同意后，现有对比链接应立即失效。
- 对比页不允许通过改变URL枚举其他用户或结果。

### 验收条件

- 单方完成测评不会暴露另一方数据。
- 邀请过期、拒绝或撤回后，API和页面都拒绝返回对比数据。
- 匿名用户绑定账号后，原邀请不丢失且不能被绑定到第二个账号。

## 8. “他人反馈”证据化功能

### 功能目标

将潜力证据模块中的“是否有他人反馈”变成可执行的产品功能。反馈只补充某条具体经历，不替代用户自述，不作为能力证明或人才选拔结论。

### 发起人流程

1. 用户选择一条已填写的具体经历。
2. 用户预览反馈人将看到的经历摘要和问题。
3. 用户主动生成有期限的反馈邀请链接。
4. 用户将链接发给了解该经历的同学、学长学姐、实习同事或社团搭档。

### 反馈人流程

- 打开链接后不需要注册完整账号。
- 页面只显示本次需要反馈的经历摘要和3–5道简短问题。
- 提交后即完成，不强制填写手机号、邮箱或其他资料。
- 如需提供联系方式，必须为明确的可选项，并单独说明用途。

### 数据处理

- 反馈响应绑定具体的 `evidenceItemId`，不只绑定用户。
- 报告中将自述和他人反馈分开呈现，标注来源和未经核验属性。
- 如需呈现“与自述一致 / 有出入”，必须保留原始反馈摘要供用户判断，不用未经验证的自动分类代替原文。
- 反馈人可以在提交前预览将被保存的内容。

### 隐私要求

- 反馈邀请只暴露回答本次问题所需的经历摘要，不显示用户的完整测评结果、其他经历或账号资料。
- 链接使用不可猜测的一次性或有期限 token，不使用自增ID。
- 需要为未注册反馈人的数据定义保留期、删除方式和联系方式。
- 正式开发前，需要核对第三方未注册用户反馈数据的隐私与合规要求。

### 验收条件

- 反馈人无法通过链接查看用户完整结果。
- 过期、撤回或已关闭的邀请无法继续提交。
- 反馈内容不会覆盖用户的自述证据。
- 可选联系方式未填写时，反馈仍可正常提交。

## 9. 隐私与同意机制

本节适用于分享卡片、对比邀请和他人反馈。

### 默认状态

- 默认为关闭、未生成、未同意。
- 用户必须通过明确动作发起。
- 页面不使用预选同意框。
- 不将“继续使用”视为分享、对比或第三方反馈的默认同意。

### 同意内容

触发前需要说明：

- 什么数据将被生成、共享或展示。
- 谁可以看到。
- 有效期多长。
- 如何撤回。
- 撤回后已经被他人保存的图片无法由系统远程删除。

### 数据保留与删除

- 每种邀请数据定义明确的过期和清理策略。
- 用户可查看已发起的邀请、状态和到期时间。
- 用户可撤回未过期的邀请。
- 第三方反馈人的删除请求处理方式需要在上线前明确。

# 四、建议实施顺序

1. 统一视觉变量、移动端版式和模块进度组件。
2. 大五与霍兰德图表，同时验证图片/PDF导出链路。
3. 独立打印样式与 PDF 逐页验收。
4. 结果分享卡片。
5. 双方同意的结果对比。
6. 他人反馈证据化功能，在隐私、保留和删除规则确认后开发。

## 上线前必须确认

- 报告和分享卡片使用的中文字体与商业授权。
- 短链和二维码的域名、过期与撤回策略。
- 对比功能的双方同意文案。
- 未注册反馈人数据的隐私告知、保留期和删除机制。
- 服务端图片渲染的资源成本、超时、重试和清理策略。
