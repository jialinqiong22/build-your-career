## 1. 产品定义

### 1.1 产品名称

- 中文名：观己
- 英文名：Build Your Career
- 产品描述：面向本科生、硕士生和应届毕业生的个人职业定位工具。

### 1.2 核心问题

产品帮助用户回答四个问题：

1. 什么类型的任务会吸引我？
2. 我通常如何做事和与环境互动？
3. 什么值得我长期投入？
4. 我已经在哪些真实行为中表现出潜力，需要什么成长条件？

九型动机反思只在深度版中作为补充，回答“我为什么可能这样选择”，不参与四维核心结论。

### 1.3 产品承诺

产品输出的是：

- 当前个人定位画像；
- 偏好的任务、贡献方式和工作环境；
- 价值取舍与潜在冲突；
- 已有行为证据与待验证假设；
- 下一阶段可执行的探索任务。

产品不承诺：

- 测出唯一正确职业；
- 给出岗位成功率、录用率或薪资预测；
- 通过人格结果证明用户具备某项能力；
- 替代心理诊断、医疗建议或正式人才选拔；
- 在没有岗位数据库的情况下生成所谓精确岗位匹配率。

### 1.4 目标用户

- 本科在读学生；
- 硕士在读学生；
- 应届毕业生；
- 实习和项目经历较少、暂时没有明确方向的用户；
- 已有模糊或明确方向，希望验证个人定位的用户。

产品不根据学校、学历或年级推断用户能力，也不以是否读研决定报告权重。

## 2. 账户、注册与服务边界

### 2.1 注册与登录方式

面向新用户提供两个主要入口：

1. **微信扫码登录／注册**；
2. **手机号注册／登录**。

登录与注册使用同一个入口。系统根据身份是否已存在自动判断：已有账号则登录，新身份则在用户同意服务条款和隐私政策后创建账号并自动登录。

现有邮箱账号不得因V5升级失效。邮箱＋密码作为迁移期的次级登录入口保留，但新用户界面优先展示微信扫码和手机号。

#### 微信扫码登录／注册

桌面端流程：

```text
点击微信扫码 → 跳转或展示微信官方授权二维码 → 用户在微信确认
→ 微信回调本站 → 服务端校验state并换取身份 → 登录或创建账号
```

要求：

- 使用微信开放平台“网站应用微信登录”OAuth能力，不使用客服微信二维码、收款码或普通静态二维码冒充登录二维码；
- 正式开发依赖审核通过的网站应用、AppID、AppSecret和已配置的授权回调域；
- PC扫码使用微信开放平台网站应用登录能力；微信内移动端访问时使用与实际资质相符的网页授权流程；
- `WECHAT_APP_SECRET` 只能保存在服务端环境变量；
- OAuth请求必须使用一次性、短时有效且服务端校验的 `state`，防止登录CSRF；
- 微信授权回调中的 `code` 只能使用一次，不写入客户端持久化存储或日志；
- 优先用可用的UnionID作为同一开放平台主体下的身份标识；无法取得UnionID时，在当前AppID范围内使用OpenID；
- 仅获取完成登录所必需的信息，不默认请求或长期保存头像、地区等非必要资料；
- 新微信用户首次登录后可以设置展示名称，但微信昵称不得直接作为唯一登录凭据；
- 用户取消授权时返回登录页，并保留手机号登录入口。

微信官方能力介绍：<https://open.weixin.qq.com/>。正式接入前需以微信开放平台当时的审核要求和网站应用登录文档为准。

#### 手机号注册／登录

V5推荐采用“手机号＋短信验证码”作为主要方式，而不是只接受一个未经验证的手机号和密码。

```text
输入手机号 → 完成人机验证 → 请求短信验证码 → 输入验证码
→ 服务端验证 → 登录已有账号或创建新账号 → 自动登录
```

第一版范围：

- 默认支持中国大陆 `+86` 手机号；
- 验证码6位数字，5分钟内有效；
- 同一验证码只允许成功使用一次；
- 发送后60秒内不可重复发送；
- 单手机号、单IP和单设备设置小时及每日频率限制；
- 请求短信前完成Turnstile服务端验证，减少短信轰炸和成本滥用；
- 验证码在数据库中只保存安全哈希，不保存明文；
- 连续输错达到上限后使当前验证码失效；
- 无论手机号是否存在，接口对外使用一致文案，避免账号枚举；
- 注册成功后自动登录，并消耗免费测评机会时绑定当前用户ID。

短信供应商、短信签名、模板审核和单价在开发前另行确认。开发环境不得真实发送短信，应使用仅限本机／测试环境的固定测试通道。

#### 账号绑定与冲突处理

- 登录用户可在账号设置中绑定微信或手机号；
- 不因微信昵称、手机号相似或相同展示名称自动合并账号；
- 绑定新身份前必须重新验证当前会话，并完成新身份的OAuth或短信验证；
- 一个微信身份或手机号只能绑定一个用户；
- 如果待绑定身份已属于其他账号，停止操作并进入人工申诉，不自动覆盖；
- 用户解绑前必须至少保留一种可用登录方式；
- 账号合并不属于V5第一版自动化范围。

#### 微信资质未就绪时的降级

微信扫码登录只有在网站应用审核、回调域和正式AppID配置完成后才启用。资质未就绪时：

- 线上界面隐藏或明确标注“微信登录暂未开放”；
- 手机号注册／登录保持可用；
- 不使用个人微信二维码替代身份认证；
- 不以随机Vercel Preview域名作为正式微信OAuth回调域。

## 4. 大五人格

### 4.1 免费IPIP-50

- 50题；
- 开放性、责任心、外向性、宜人性、情绪稳定性各10题；
- 五级作答：非常不符合、比较不符合、不确定、比较符合、非常符合；
- 正向与反向题交错；
- 输出五个一级维度，不输出30个细分面向。

IPIP官方说明其题目与量表属于公有领域，可复制、编辑、翻译和用于商业产品：<https://ipip.ori.org/>。

### 4.2 付费120题进阶版

- 5个一级维度；
- 每个一级维度6个细分面向；
- 每个细分面向4题；
- 合计120题；
- 报告输出5个一级维度和30个细分面向。

一级维度和细分面向：

| 一级维度 | 六个细分面向 |
| --- | --- |
| 开放性 | 想象构思、审美感受、情绪觉察、探索意愿、思辨兴趣、观念开放 |
| 责任心 | 自我效能、条理性、责任意识、成就驱动、自律坚持、审慎决策 |
| 外向性 | 人际亲近、群体参与、主动表达、行动活力、刺激需求、积极情绪 |
| 宜人性 | 信任倾向、真诚直接、助人倾向、合作意愿、谦逊程度、共情关怀 |
| 情绪稳定性 | 焦虑敏感、愤怒反应、低落倾向、自我意识、冲动控制、压力脆弱性 |

“焦虑敏感”“低落倾向”等仅为人格倾向描述，不得解释为临床疾病。

### 4.3 免费到付费的答案处理

IPIP-50与120题进阶版是独立工具，不能把免费50题与新增70题拼接后宣称为标准120题。

- 升级用户需要独立完成120题；
- 免费结果可保留作用户自我对照；
- 两次结果不做精确涨跌或百分位比较；
- 中文版本须保留题目来源、翻译版本和修订记录。

## 5. 霍兰德职业兴趣

### 5.1 六个维度

- R：现实型／动手实践；
- I：研究型／研究分析；
- A：艺术型／创意表达；
- S：社会型／帮助支持；
- E：企业型／影响推动；
- C：常规型／条理组织。

### 5.2 免费18题

- 每个维度3题；
- 统一询问用户对某项活动的兴趣程度；
- 五级选项从“完全不感兴趣”到“非常感兴趣”；
- 输出RIASEC六维分数、前三位兴趣代码和兴趣集中度；
- 明确标注为项目原创快速探索题，不是标准化量表。

### 5.3 付费90题

- 每个维度15题；
- 每个维度覆盖6道活动偏好、5道任务偏好、4道环境偏好；
- 免费18题作为90题中的核心题；
- 30天内升级可复用免费18题，只完成剩余72题；
- 超过30天升级默认重新完成90题。

90题根据RIASEC公开理论自主编写，可以参考公开产品的覆盖方式，但不得逐字复制第三方测评网站题目或报告。正式名称：

> Build Your Career 霍兰德职业兴趣90题完整版——基于RIASEC理论自主开发

### 5.4 输出

- 六维分数；

- 不直接输出具体岗位匹配百分比。

## 6. 职业价值观40题

正式名称：

> Build Your Career 职业价值观测评——基于公开职业价值观与职业锚理论自主开发

明确声明：非施恩职业锚原版，非舒伯WVI原版，未经标准化常模验证。

### 6.1 结构

- 10个维度；
- 30道重要程度题，每维度3题；
- 10道强制权衡题；
- 合计40题。

十个维度：

1. 收入回报；
2. 成长学习；
3. 稳定安全；
4. 自主自由；
5. 影响力；
6. 专业积累；
7. 创造创新；
8. 挑战成就；
9. 关系归属；
10. 生活平衡。

### 6.2 作答与输出

重要程度题使用五级量表。强制权衡题让用户在两个都具有吸引力的条件之间选择。

输出：

- 前三项核心价值观；
- 两项次优先价值观；
- 当前最低优先级；
- 价值观冲突；
- 不可妥协条件；
- 用户愿意接受的交换条件。

价值观没有道德高低，不因用户重视收入、稳定或生活平衡而给出负面判断。

## 7. 潜力证据与成长条件

该模块不是心理量表，不要求用户给自己的“能力”打分。

### 7.1 结构

```text
12组行为证据问题 + 6组成长条件问题 = 18组
```

六类行为证据，每类2组：

- 学习与自驱；
- 分析与解决问题；
- 创造与表达；
- 执行与交付；
- 协作与组织；
- 影响与服务。

每组先询问是否有相关经历；选择“有”后，按需展开：

- 当时需要解决什么问题；
- 用户本人采取了什么行动；
- 持续时间；
- 产生的结果；
- 是否存在作品、数据、证书或第三方反馈。

六组成长条件覆盖：

- 清晰指导需求；
- 自主空间需求；
- 反馈频率；
- 任务难度偏好；
- 协作密度；
- 节奏与压力条件。

### 7.2 证据强度

每条行为证据按结构化信息计算0–4分：

| 分值 | 含义 |
| --- | --- |
| 0 | 没有相关经历 |
| 1 | 只有抽象或模糊描述 |
| 2 | 有具体场景和本人行动 |
| 3 | 有明确结果 |
| 4 | 有数据、作品或第三方反馈 |

总分只用于证据丰富度分档：

- 0–12：证据较少；
- 13–27：证据正在形成；
- 28–39：证据较丰富；
- 40–48：证据较强。

该分数不对用户展示为“能力分”。字数、学历、学校和年级不增加分数。所有证据默认属于用户自述，未经外部核验。

### 7.3 报告分流

- 证据较少：探索导向，强调下一步试做；
- 证据正在形成：同时呈现已有线索和待验证假设；
- 证据较丰富：识别重复出现的行动模式；
- 证据较强：分析可迁移贡献方式及其边界。

不使用固定的四维百分比，也不生成综合总分。

## 9. 综合分析方法

### 9.1 计算与生成职责

- 价值观排序及冲突；
- 证据丰富度分档；
- 报告中允许使用的事实数据。

Kimi负责：

- 将已经计算的数据转化为清晰中文；
- 解释四维之间的支持关系和冲突；
- 根据用户证据形成有依据的定位假设；
- 生成验证任务；
- 生成结构化报告内容。

Kimi不得：

- 自行重算或修改量表分数；
- 编造用户经历、技能、家庭情况或求职目标；
- 从学校、专业、性别或学历推断能力；
- 输出心理疾病判断；
- 生成岗位成功率、录用概率或薪资承诺；
- 把九型结果写入四维核心评分；
- 在当前版本调用联网搜索或外部岗位数据库。

### 9.2 证据标签

每个关键结论必须标注一种来源：

- `量表倾向`；
- `价值观选择`；
- `行为证据`；
- `综合推测`；
- `待验证`。

只由LLM推断、没有量表或行为支持的内容必须标记为“综合推测”或“待验证”。

## 10. Kimi LLM 集成规格

### 10.1 接入方式

采用Kimi开放平台中国区API：

- Base URL：`https://api.moonshot.cn/v1`；
- 协议：兼容OpenAI Chat Completions；
- Node.js客户端：官方兼容的 `openai` SDK；
- API Key仅存在于Vercel服务端环境变量；
- 浏览器不得直接调用Kimi，不得接触API Key。

Kimi官方接入说明：<https://platform.kimi.com/docs/api/overview>。

### 10.2 模型策略

初始候选默认值：

```text
KIMI_MODEL=kimi-k3
KIMI_BASE_URL=https://api.moonshot.cn/v1
MOONSHOT_API_KEY=<server secret>
KIMI_PROMPT_VERSION=positioning-v1
```

选择Kimi K3的理由：官方当前将其列为知识工作和深度推理旗舰模型，并说明其稳定支持Structured Output。模型名称必须通过环境变量配置，不写死在业务逻辑中，以便模型下线、价格变化或评测失败时切换。官方模型列表：<https://platform.kimi.com/docs/models>。

生产启用前必须用真实脱敏样本比较至少一个备用模型。不得仅因模型“最新”就直接上线。

### 10.3 结构化输出

使用：

```json
{
  "type": "json_schema",
  "json_schema": {
    "name": "career_positioning_report",
    "strict": true,
    "schema": {}
  }
}
```

业务层仍须执行二次Schema校验。模型输出只保存 `message.content` 中的最终JSON，不把 `reasoning_content` 展示或存入用户报告。Kimi官方建议生产下游使用 `json_schema` 与 `strict: true`：<https://platform.kimi.com/docs/guide/response_format>。

### 10.4 LLM输入

发送给Kimi的内容只包括：

- 匿名assessment ID；
- 规则版本、题库版本和prompt版本；
- 已由程序计算的量表结果；
- 用户主动填写的经历与成长条件；
- 方向清晰度；
- 报告语言和套餐类型。

不得发送：

- 手机号；
- 邮箱；
- 用户名；
- 密码或会话凭证；
- 付款信息；
- Turnstile token；
- 微信号；
- 不生成报告所必需的数据库字段。

### 10.5 LLM输出Schema

第一版报告JSON至少包含：

```text
reportVersion
assessmentId
positioningSummary
confidenceStatement
hollandInterpretation
bigFiveInterpretation
valuesInterpretation
evidenceInterpretation
crossDimensionSupports[]
crossDimensionTensions[]
preferredTasks[]
preferredEnvironments[]
growthConditions[]
avoidConditions[]
evidenceBackedFindings[]
hypothesesToValidate[]
validationPlan[]
limitations[]
enneagramReflection | null
```

每条结论对象至少包含：

```text
statement
evidenceType
evidenceRefs[]
certainty: supported | tentative | insufficient
```

### 10.6 失败处理

报告生成状态：

```text
not_started → queued → generating → validating → completed
                                      ↘ failed
```

规则：

- 同一次生成使用唯一幂等键；
- 网络错误和429最多自动重试2次，采用指数退避；
- 4xx参数错误不盲目重试；
- `finish_reason=length` 视为失败，不使用残缺报告；
- JSON解析或Schema校验失败时最多进行一次修复调用；
- 超过失败次数后保留答案，允许用户稍后重试；
- 失败不重复扣减用户的报告权益；
- 不向用户展示原始模型错误或服务端日志。

### 10.7 质量控制

上线前建立至少30份脱敏测试样本，覆盖：

- 证据极少；
- 证据丰富；
- 各维度高度一致；
- 兴趣与价值观冲突；
- 全部维度接近；
- 多道题跳过；
- 明确目标型；
- 排除型；
- 用户文本中包含与提示词冲突的指令；
- 敏感情绪表达。

评价指标：

- 是否忠于输入；
- 是否存在编造；
- 是否混淆兴趣与能力；
- 是否出现职业或学校刻板印象；
- 是否区分证据与假设；
- 建议是否可执行；
- 同一输入重复生成是否保持核心结论稳定；
- 输出是否通过Schema校验。

任何模型或prompt版本更新都必须重新运行该评测集。

### 10.8 成本与日志

每次调用记录：

- provider；
- model；
- promptVersion；
- inputTokens；
- outputTokens；
- cachedTokens（如API返回）；
- latencyMs；
- retryCount；
- finishReason；
- validationStatus；
- 估算成本。

日志不得记录完整用户自述、API Key或PII。Kimi提供Token估算接口，可在开发与成本测试阶段使用：<https://platform.kimi.com/docs/api/estimate>。

## 13. 数据模型草案

当前 `users` 和 `user_sessions` 需要兼容迁移。由于微信用户和短信验证码用户不一定拥有密码，现有 `users.password NOT NULL` 及“邮箱／手机号二选一”约束不能直接沿用。迁移不得让已有邮箱账号失效。

V5建议将“用户主体”和“登录身份”分离：

### 13.1 users与auth_identities

`users` 保存产品内用户主体：

- id；
- displayName；
- createdAt；
- updatedAt；
- deletedAt。

`auth_identities` 保存登录身份：

- id；
- userId；
- provider：email_password、phone_otp、wechat；
- providerSubject：标准化邮箱、E.164手机号、微信UnionID或OpenID作用域标识；
- passwordHash：仅email/password身份可用；
- verifiedAt；
- createdAt；
- lastUsedAt。

`provider + providerSubject` 必须唯一。现有用户名可迁移为展示名称，但不继续作为所有新账号的必填登录凭据。

### 13.2 oauth_states与sms_verification_challenges

`oauth_states`：

- stateHash；
- provider；
- redirectPath；
- expiresAt；
- consumedAt。

`sms_verification_challenges`：

- id；

- codeHash；
- purpose：login、bind_phone；
- attempts；
- expiresAt；
- consumedAt；
- createdAt。

验证码记录按短周期自动清理，不得用于营销画像。

## 15. 隐私、安全与产品伦理

- 注册信息与测评答案分表存储；
- 手机号使用E.164格式标准化，并在日志中脱敏；
- 短信验证码只保存哈希并短期保留，禁止在日志中输出；
- 微信AppSecret、短信服务密钥和OAuth token仅存在服务端；
- OAuth `state` 一次性使用并设置短有效期；
- 登录成功后重新生成会话，防止会话固定；
- 绑定或解绑登录身份需要近期重新认证；
- Turnstile用于短信发送防刷，但不能替代短信验证码或OAuth回调校验；
- 密码继续使用bcrypt哈希，不明文保存；
- Kimi Key、支付配置和报告签名密钥仅存在服务端；
- 发送Kimi前移除手机号、邮箱、用户名和微信号；
- 用户提交开放文本前展示“内容会发送给第三方大模型生成报告”的明确同意；
- 用户拒绝LLM处理时可保留答案，但不能生成AI付费报告，应进入退款或人工替代流程；
- 用户可以导出自己的结果并申请删除账号和测评数据；
- 报告链接必须鉴权或使用短期签名URL；
- R2对象默认不以可猜测文件名公开；
- 管理员查看订单不自动获得查看完整测评内容的权限；
- 对用户文本进行提示词注入隔离，用户自述只能作为数据，不作为模型指令；
- 输出必须附“职业探索用途、非心理诊断、非结果保证”声明。

正式上线前仍需确认Kimi开放平台当时适用的数据处理条款、数据保留政策和商业使用条款。

## 17. 验收标准

### 17.1 题库与计分

- 各模块题量与维度覆盖符合本规格；
- 正反向计分有自动测试；
- 免费50题不能与付费120题错误拼接；
- 霍兰德18题可按规则复用至90题；
- 九型整项跳过不影响四维结果；
- 证据分档不依据字数、学校、学历和年级；
- 任何模块缺失时不伪造完整结论。

### 17.2 权益

- 免费正式机会每账号一次；
- 79与199权益严格区分；
- 未付款用户不能调用付费报告接口；
- 79用户不能访问九型和人工最终版发布功能；
- 升级只补差价一次，避免重复权益；
- 管理员确认订单有审计记录。

### 17.3 注册与登录

- 新用户可通过微信扫码或大陆手机号完成注册并自动登录；
- 微信身份已存在时直接登录，不重复创建用户；
- 手机号已存在时直接登录，不重复创建用户；
- OAuth回调拒绝无效、过期、重复或不匹配的state；
- 短信验证码过期、重复使用、超限和连续输错均被拒绝；
- 请求短信前执行Turnstile服务端验证和频率限制；
- API响应不泄露某手机号是否注册；
- 一个外部身份不能绑定两个用户；
- 用户不能解绑最后一种登录方式；
- 已有邮箱账号在迁移后仍可正常登录；
- 微信资质或配置缺失时，手机号登录不受影响；
- AppSecret、短信密钥、验证码和OAuth token不出现在客户端、Git或日志中。

### 17.4 Kimi

- API Key不进入客户端bundle、日志或Git；
- 请求不包含PII；
- 分数由程序计算而非模型计算；
- 输出必须通过JSON Schema和业务规则校验；
- 编造经历的测试样本不得通过验收；
- 超时、429、无效JSON和输出截断均有用户可理解的失败状态；
- 重试不重复扣减权益；
- 模型和prompt版本可追踪。

### 17.5 报告与PDF

- 免费报告不错误显示为完整职业定位；
- 79报告为6–8页目标内容量；
- 199会前稿与最终稿有明显状态区分；
- PDF中文字体、分页、图表、页眉页脚和打印结果在手机与桌面端检查；
- 用户不能通过修改URL读取他人报告；
- 过期签名链接无法访问R2文件。

### 17.6 咨询运营

- 用户能看到服务范围、时长、顾问经验、改期和退款规则；
- 79沟通不默认触发人工PDF重写；
- 199只有在咨询完成并由顾问确认后发布最终PDF；
- 咨询完成、取消和未出席状态可记录。
